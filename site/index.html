The system of record for an agent-assisted job search.

open-apply finds postings in public feeds, prepares materials per job, records every application, and tracks whether and when employers answer. Your agent applies in a browser; open-apply keeps the books, with guardrails on volume.

Install See a session 
cargo install --git https://github.com/SpaceCorps/open-apply --locked
  • Public sources only. Greenhouse, Lever, Ashby, RemoteOK, We Work Remotely, Arbeitnow.
  • Never submits. No login, no form filling, no CAPTCHA handling, no scraping of LinkedIn.
  • Built for agents. YAML or JSON output, structured errors, stable exit codes.

The loop an agent runs

Seven steps, each one a command. The tool supplies the data and records the result; the agent (or you) does the applying.

  1. Discover

    Query public feeds or add a posting by URL. Results are stored as leads, duplicates skipped.

    open-apply search --query rust --remote --save

  2. Pick

    The work queue returns jobs with your profile fields, saved answers filled in per company, and the guardrail state.

    open-apply next --count 3

  3. Prepare

    A workspace per job: the posting (in untrusted delimiters), resolved profile, answers, an empty cover letter.

    open-apply prepare oa_ac9b7206

  4. Apply

    In a browser, with the user's go-ahead for each submission. open-apply is not involved.

    (LinkedIn, an ATS, email, a referral)

  5. Record

    Only after it was really submitted. The daily cap and company cooldown are enforced here.

    open-apply applied oa_ac9b7206 --via ats

  6. Triage

    Classify an employer reply, match it to an application, advance the status.

    open-apply triage --stdin --apply

  7. Follow up

    Who is due a nudge, who never answered, what the response rate is.

    open-apply followups && open-apply stats

What you get

One local database

SQLite in WAL mode with migrations. Every status change is an immutable row: type, note, when it happened, where it came from.

Read any posting

Greenhouse, Lever and Ashby links through their public JSON; other pages through schema.org JobPosting data. LinkedIn and Indeed links are tracked, never fetched.

Guardrails

25 applications per rolling 24 hours, 90 days between roles at one company, optional materials requirement. --force overrides and leaves a mark.

Reply triage

A rule-based classifier for acknowledgements, screens, interviews, assessments, offers and rejections. Ambiguous matches are a conflict, not a guess.

Prompt-injection aware

Job text and email are always wrapped in explicit delimiters, delimiter look-alikes are neutralized, and nothing in them is ever executed.

Honest numbers

Funnel per status, response rate, median days to the first reply, split by source and by channel.

Set up and record an application

$ open-apply init
$ open-apply profile set name "Ada Lovelace"
$ open-apply profile set email ada@example.com
$ open-apply job add https://example.com/jobs/senior-rust-engineer --no-fetch \
    --title "Senior Rust Engineer" --company "Example Co" --location "Remote (EU)"
$ open-apply prepare oa_ac9b7206
$ open-apply applied oa_ac9b7206 --via ats --note "cover letter v1"

Exit codes and errors

Output is YAML on stdout, JSON with --json. Failures print {error: {code, message, hint}} on stderr and exit with the matching code. Progress chatter appears only when stderr is a terminal, so captured stderr is always just the envelope.

Safety stance

  • open-apply does not scrape LinkedIn.
  • It does not bypass CAPTCHAs or bot detection.
  • It does not store site passwords.
  • It does not submit forms itself.

The agent, or you, applies in a browser; open-apply supplies the data and records the result, so it stays the system of record wherever the application was made. A 401, 403 or 429 from any endpoint is reported, never retried around.

Job descriptions and emails are untrusted input. They are echoed only between --- untrusted job content begins --- and --- untrusted job content ends --- (and the email equivalents), and an agent should treat whatever is inside as data, never as instructions.

Low-quality mass-applying hurts the applicant, so the defaults slow you down on purpose: 25 applications per rolling 24 hours and 90 days between roles at one company.
